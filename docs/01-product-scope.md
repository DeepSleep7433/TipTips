# 产品范围与行为规则

TipTips 的目标是让个人计划能够连续地经过记录、整理、安排、执行和回顾。待办与日历是确定性的基础，AI 提供理解和执行能力，桌面与消息渠道让用户随时能够查看、指挥和纠正。

## 1 产品约束

| 编号 | 要求 | 对设计的影响 |
| --- | --- | --- |
| R01 | 可安装的原生 Windows 应用 | 主窗口、设置、日历、桌宠使用原生桌面技术，不使用 Electron、Tauri 或 WebView 承载业务 UI |
| R02 | 可在后台静默运行 | 关闭主窗口后调度继续；前台界面和后台核心具有独立生命周期 |
| R03 | 个人待办与日历 | 无网络、无模型账号时仍可创建、查看、修改和完成本地任务 |
| R04 | Hermes 助理 | 真实连接 Hermes 引擎，展示引擎状态、能力、会话和运行结果 |
| R05 | 应用 MCP 与配置接口 | 同时支持协议连接与常规应用 API；提供可理解的授权、参数和诊断界面 |
| R06 | 委派给 Codex 与 Claude Code | 在已绑定执行节点和工作区运行，能够查看进度、处理审批、停止和回收结果 |
| R07 | 推送和邮件交互 | 消息可以提醒，也能以已授权的回复动作修改任务或继续会话 |
| R08 | 可选桌宠 | 快速捕获、问答、提醒、运行状态；可以完全关闭 |
| R09 | Windows 或 macOS 服务主机 | 核心业务不依赖 Windows UI；局域网客户端经认证访问服务 |
| R10 | 多模型提供方 | OpenAI、Anthropic、本地 LLM 分别适配，不把协议兼容等同于能力一致 |
| R11 | 尽可能优化性能 | 优先低空闲消耗和交互延迟，重工作有队列、预算、取消和隔离 |
| R12 | 开源与交接 | MIT 公开仓库；提供 sol6.1 max 能分阶段执行的规格和验收标准 |

本轮交付只包含文档、许可证和贡献说明。后续实现由所有者另行启动。

## 2 产品角色与默认范围

首个完整版本面向一个所有者、多台可信设备；设备撤销与空间隔离从底层建模。多人协作、组织管理和公开 SaaS 不列入首个完整版本。

Windows 11 x64 为第一客户端验收平台。Windows ARM64 可作为后续发布目标；Windows 10 支持需依据届时运行时和系统生命周期单独决定。macOS 第一阶段提供后台主机，不承诺完整 Mac GUI。服务主机不需要显示器，也不需要一直打开客户端。

提供三种安装用途：本机个人模式、连接已有主机的客户端模式、局域网主机模式。设置页必须清楚显示当前数据保存在哪台主机、任务将在哪台设备执行。

## 3 关键使用闭环

### 快速记录并安排

用户通过主窗口、全局快捷键、托盘或桌宠输入“周五前完成季度总结”。系统先保存原始输入，解析为候选待办，显示解析出的日期与时区。用户可直接修改。安排到周四 15 时后创建关联时间块，完成待办后同步取消尚未到达的提醒。

### 在有空时间执行

用户说“明天有一小时空闲，帮我安排这三件事”。助理读取用户授权的日历范围和任务，不直接覆盖既有日程；返回冲突、建议时间块和预计时长。明确的用户命令或已经设置的自动化授权可直接落地范围内操作，歧义或超出授权的操作进入提案。

### 委派编码任务

用户在项目详情中选择工作区、执行节点、Codex 或 Claude Code，填写目标和完成条件。系统显示写入范围、预算与允许操作。执行器运行时持续展示结构化进度，遇到额外授权时等待用户。结果先进入“待验收”，不会因为执行器说“完成”而自动完成业务待办。

### 离开电脑后交互

后台主机在运行完成时发送结果摘要；用户通过已绑定的邮件回复“稍后提醒我”或经验证的交互按钮延后。外部消息解析成有来源的输入，不把任意邮件正文当成系统授权。敏感操作在可信客户端完成确认。

### 家庭局域网

Mac 或另一台 Windows 机器保存个人空间并运行后台。Windows 客户端显示数据、承接原生通知和桌宠。需要操作当前电脑文件的任务交给当前电脑的执行节点；远程主机不能凭一个 Windows 路径访问本地磁盘。

## 4 通用行为规则

1. 原始输入先持久化，AI 失败不丢失记录。用户能查看输入被转换成了哪些对象。
2. 截止日期、执行时间块、提醒时间分开；修改其中一项不能隐式改变其他项。
3. 默认关闭窗口后退出重量级主窗口，保留轻量会话代理和核心。托盘提供“打开”“暂停自动化”“退出前台”“停止本机核心”等含义明确的操作。
4. 系统休眠或关机时，不承诺本机代码继续运行。错过的提醒按规则补偿；持续服务需要保持运行的主机。
5. 所有写操作有稳定操作标识；重复点击、重连、渠道重投不能产生重复待办或重复委派。
6. 用户取消仅表示发起停止；执行器确认退出后才显示已取消。已经发生的外部副作用保留记录。
7. 助理、MCP 和邮件不能直接改业务数据库，必须通过业务 Interface。
8. 远程断开时显示数据新鲜度和待同步状态；不静默把远程空间切成另一个本机空间。
9. 运行权限、预算和数据发送范围在委派开始时固定快照；新增范围需新增授权。
10. 外部系统返回成功、用户实际读到通知、业务目标验收成功是三个不同事实。

## 5 首个完整版本的能力层次

| 里程碑 | 用户得到什么 | 范围 |
| --- | --- | --- |
| 本地核心预览 | 能安装、记录、安排和收到提醒 | 待办、内置日历、重复规则、托盘、持久调度、备份 |
| 助理预览 | 能与 Hermes 或直连模型交流并形成提案 | 模型、Hermes、会话、MCP、审批与预算 |
| 委派预览 | 能受控执行编码任务 | Codex、Claude Code、节点与工作区、产物验收 |
| 个人助理完整版本 | 多渠道、桌宠和局域网连续使用 | 邮件、推送、外部日历同步、桌宠、服务安装、远程客户端 |

完整版本不能用“本地待办预览”冒充。各里程碑允许先验收再继续，产品目标保持不变。

## 6 扩展范围

以后可增加移动客户端、完整 macOS 原生客户端、语音输入输出、更多渠道、CalDAV 双向同步、更丰富桌宠与知识检索。首期不做多主自动选举、不要求安装 PostgreSQL/Redis、不训练大模型、不实现通用远程桌面控制。

全局键盘记录、持续屏幕采集与任意应用自动点击都不是当前产品必要能力。后续如确有需求，应作为独立可关闭的能力设计。

## 7 产品层验收

验收至少包括：无模型仍可管理计划；关闭窗口后提醒仍有效；错误日期可纠正；两次相同渠道输入只产生一个对象；编码任务可暂停等待审批；远程主机重启后状态可恢复；桌宠关闭后相关渲染停止；十万条历史记录不阻塞常规操作。

具体用例与性能口径见 [路线](11-delivery-roadmap.md) 和 [性能计划](10-performance-plan.md)。
