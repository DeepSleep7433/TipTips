# 日历通知与桌宠

时间和通知是产品可靠性的核心。日历决定“何时发生”，调度决定“何时处理”，渠道决定“如何触达”，桌宠提供一个可关闭的交互入口。

## 1 日历产品内容

支持日/周/月/议程视图、多日历颜色、任务时间块、全天事件、重复事件、单次例外、冲突提醒、拖动改期、快速创建和按项目筛选。

拖动事件先展示新时间与冲突，再根据已有授权提交。拖动重复事件时选择本次、以后或整个系列；外部只读日历不能出现可提交的编辑状态。保存失败恢复原显示，并保留用户修改草稿。

待办截止日期是 deadline 标记；排期时间块是工作安排。删除时间块不删除待办，完成待办不删除历史时间块，但撤销未来提醒。

## 2 外部日历接入顺序

| 层次 | 范围 | 验收重点 |
| --- | --- | --- |
| 内置日历 | 本机存储、重复与提醒 | 时区、DST、实例例外 |
| ICS 导入/导出/订阅 | 手动文件与只读订阅 | UID、SEQUENCE、RECURRENCE-ID、重复导入 |
| 一个提供方的只读同步 | Google Calendar 或 Microsoft Graph | 权限、增量、删除、重复系列 |
| 双向同步 | 同一提供方先完整验收 | ETag/版本冲突、撤销、断线补偿 |
| 扩展提供方 | 另一个提供方与后续 CalDAV | 保持同一业务语义 |

Google 的增量同步需要维护同步令牌并处理失效；Graph 的日历视图增量查询与查询范围有关。两个 Adapter 分别保存游标及其查询条件，不能设计成“所有日历一个全局时间戳”。[Google 同步](https://developers.google.com/workspace/calendar/api/guides/sync)，[Microsoft Graph 日历增量](https://learn.microsoft.com/en-us/graph/delta-query-events)

外部推送是“有变化，需拉取”的提示，正式数据以带权限的增量查询为准。订阅需续期；回调不可用时使用有限频率轮询。LAN 主机默认不为此暴露公网端口。

## 3 同步冲突

保存 external_calendar_id、external_event_id、recurrence_identity、etag、last_synced_revision 与本地映射。独立字段变化可按规则合并，时间、参与者、取消和重复规则冲突进入比较界面。

发送邀请与只保存个人时间块不同；编辑参与者可能发出邮件，必须纳入操作影响。双向更新用来源标识与版本避免回声循环。某个外部对象被取消后，不能在下一次本地同步中无意重建。

## 4 提醒与错过触发

提醒可以为绝对时点、相对事件开始/截止、重复提醒、未处理后升级。每条规则提供未来若干次触发预览和使用的时区。

默认策略：短时错过的普通提醒合并为一次补提醒；很久之前的提醒进入摘要。用户明确设定的自动化分别选择跳过、补一次或有限补齐，补齐上限必须固定。发送外部消息和执行代码默认不因恢复休眠无限追补。

机器休眠、断电或服务停止时无法保证本机即时处理；恢复后对账。要在电脑关闭期间继续处理，使用保持运行的服务主机。是否支持 OS 计划通知作为额外保障在平台验证后决定，不能与核心重复投递。

## 5 通知策略

一个通知意图包括原因、对象引用、优先级、有效期、可见摘要、动作集合和去重键。投递策略决定目标设备、渠道、时间窗与升级方式。

| 优先级 | 例子 | 默认行为 |
| --- | --- | --- |
| 普通 | 今日回顾、任务变化 | 应用收件箱或合并摘要 |
| 时间相关 | 日程即将开始、待办到期 | 首选活跃设备 Toast，可同步桌宠 |
| 需要操作 | 执行器等待输入/审批 | 提醒并保留待处理标识，不反复打断 |
| 故障 | 主机离线、运行失败 | 去重后告知，恢复可合并更新 |

勿扰不暂停业务状态保存；通知进入 suppressed 或延后。没有变化的周期检查保持安静。用户可控制音效、预览内容、桌宠气泡与多设备策略。

## 6 Windows 通知与推送

Windows 本地通知通过会话代理调用受支持的通知 API，动作进入相同业务命令。通知点击要能定位目标对象，重复点击不能重复完成待办。

WPF 可使用 Windows App SDK 的 AppNotificationManager。WNS 是另一种远程推送机制，包含应用注册和打包条件；首版不能把 LAN SSE 当成系统云推送，也不能承诺所有未打包场景都支持后台 WNS 激活。[Windows 通知说明](https://learn.microsoft.com/en-us/windows/apps/develop/notifications/)

基础方案：CoreHost → 已连接 SessionAgent → 本地 Toast。离线移动触达先通过邮件或用户选择的推送服务；WNS 在完成注册与系统验收后作为独立渠道加入。

可选渠道候选包括自托管/托管的推送服务、企业消息或机器人服务，具体选型在实施时核实账户、区域、费用和回调能力。本阶段不承诺任一第三方免费或永远可用。

## 7 邮件发送与回复

第一版先提供已授权的摘要、到期和完成通知；支持明确收件人、主题、纯文本/HTML 内容和对象链接。外部收件人必须在通知规则中配置，不能从检索内容临时抽取后直接发送。

入站使用官方邮箱 API 或 IMAP/OAuth Adapter；仅在用户选择的邮箱和文件夹处理。按提供方消息 ID 去重，保存引用链和相关对象；不扫描全部历史邮箱作为默认初始化。

回复关联采用 Message-ID、In-Reply-To、受控 Reply-To 标识以及短期交互令牌。仅匹配 From 地址不足以证明用户授权。令牌必须绑定对象、允许动作、用户与有效期，并防重放。

低风险回复如“延后十分钟”“继续解释”在已验证身份和限定范围内可执行。删除大量数据、扩大工作区写权限、执行命令、付款或向新收件人发送信息必须转可信客户端处理。

避免自动回复循环：识别自动回复/退信、限制链路深度、每对象频率和每日总量。发送超时结果未知时先查询/对账；SMTP 不能提供的已读能力不在 UI 中虚构。

## 8 桌宠交互

| 入口 | 操作 |
| --- | --- |
| 单击 | 展示简洁菜单：快速记录、问助理、今日安排、待处理事项 |
| 双击或快捷操作 | 打开主窗口对应页面 |
| 拖动 | 移动到显示器内有效位置并记住偏好 |
| 提醒气泡 | 查看、延后、关闭；完成操作要显示对象 |
| 运行状态 | 显示思考、执行、等待、完成或失败的简化状态 |
| 右键菜单 | 隐藏、勿扰、外观、设置、关闭桌宠 |

鼠标穿透与互动区域分开；初次启用给出如何关闭的明确提示。宠物不夺取前台焦点，不遮挡必须操作的确认按钮，游戏/全屏/演示时可自动隐藏。

动作状态建议为 idle、attention、listening、thinking、working、waiting、success、error、sleep。角色表情只是显示映射，不能改变业务 Run 状态。

## 9 桌宠资源与性能

资源包包含名称、作者、许可、图片/序列帧、状态映射、锚点、命中区域和最大尺寸。限制解压大小、路径、分辨率、帧数与总解码内存，禁止资源包携带可执行脚本。

首期支持静态图和有限帧动画，不要求生成角色素材；资源使用来源清楚的用户素材或原创素材。Live2D/3D 等增加独立渲染和许可负担，后续单独评估。

空闲建议 4–8 FPS，交互动画最高 24 FPS，静止时停止刷新；锁屏、隐藏、全屏抑制时停止动画计时器。窗口只覆盖宠物区域，不创建全桌面透明画布。详细预算见 [性能计划](10-performance-plan.md)。

## 10 端到端验收

核心重启、SessionAgent 重启和主窗口关闭分别验证。邮件、推送和 Toast 要各自保留实际发送回执与动作结果；“已调用发送函数”不能算触达验收。

多设备用例包括一台活跃、一台锁屏、两台同时在线、某台离线后恢复。桌宠用例包含混合 DPI、显示器拔出、GPU/软件渲染、桌面切换、锁屏和长时间静止。
