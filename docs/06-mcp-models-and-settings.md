# MCP 模型与配置中心

统一设置入口应让用户知道“连接的是什么、谁会使用它、会接触哪些数据、在哪台机器执行、如何停止”。统一展示不意味着所有协议共用同一份配置或凭据。

## 1 四类配置对象

| 类型 | 例子 | 能力归属 |
| --- | --- | --- |
| 模型提供方 | OpenAI、Anthropic、本地服务 | 推理、文本、工具请求、图像等模型能力 |
| 助理与执行引擎 | Hermes、Codex、Claude Code | 自身会话、规划和执行循环 |
| MCP 工具连接 | 文件工具、应用工具、远程工具 | 协议暴露的 tools/resources/prompts |
| 业务连接 | 日历、邮箱、推送服务 | 身份授权、同步、投递、入站消息 |

同一个供应方可以出现多种类型；UI 必须分别呈现。用户填写一个 OpenAI API Key 不意味着已经配置好 Codex 执行器。

## 2 模型 Profile

每个模型 Profile 保存：显示名、提供方、协议、endpoint、模型 ID、secret_ref、默认上下文/输出预算、超时、可用能力、网络位置、隐私级别与最近探测结果。

能力矩阵至少包括文本、流、工具调用、结构化结果、图像输入、语音、上下文上限、用量回报和取消支持。能力来自提供方描述加最小探测；不能把 /models 中存在一个名字当成所有能力和账户权限都可用。

| Adapter | 处理方式 | 需要独立保留的语义 |
| --- | --- | --- |
| OpenAI | 使用受支持的 Responses 等原生接口 | 响应状态、工具事件、使用量与提供方特有选项 |
| Anthropic | 使用 Messages 等原生接口 | 内容块、工具使用、结束原因与缓存/推理选项 |
| OpenAI-compatible | 显式选择兼容协议版本与能力 | 缺失能力以 unsupported 呈现，不能静默丢字段 |
| Ollama/本地 LLM | 可选择本地原生或已验证兼容入口 | 模型加载时间、硬件压力、工具模板与上下文约束 |

本地端点的协议兼容通常有具体功能范围，不能视为官方全部接口的镜像。[Ollama 兼容性说明](https://docs.ollama.com/api/openai-compatibility)

## 3 模型选择与预算

默认由用户选择 Profile。以后可按“快速整理、日程规划、复杂委派、敏感本地处理”配置路由规则，但每条规则必须说明可发送的数据和允许的回退目标。

不自动把本地私密任务转发到云端。更换提供方不能自动重放有副作用的工具。模型失效时保存用户输入与运行状态，提供重试或改选。

运行前预留可估算的预算，结束后记实际用量；未返回计费用量时显示未知/估计，不能记为零。资金限额只是根据可观测信息尽力控制，服务端最终账单仍以提供方为准。个人、Profile 和 Run 三级限额共同生效。

上下文按任务选择资料，优先摘要和引用；历史压缩保留原文与摘要版本。模型切换导致上下文超限时展示丢弃/摘要范围，不无声裁掉关键验收条件。

## 4 MCP 生命周期

MCP 标准传输包括本地 stdio 与 Streamable HTTP；旧 HTTP+SSE 只能作为兼容分支。初始化、能力协商和协议版本必须真实执行。[MCP Transport](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)

连接流程：创建配置 → 校验来源与参数 → 配置凭据 → 启动/握手 → 发现能力 → 用户选择授权范围 → 启用。工具名称以连接命名空间隔离，避免不同服务器的同名工具混淆。

本地 stdio 配置保存已确认的可执行文件、参数列表、工作目录、环境白名单、运行节点与版本。不要把模型文本拼接成 shell 命令；安装包命令和工具参数分开处理。

远程连接保存 endpoint、认证方式、协议能力、证书/受信任来源与超时。OAuth 遵循协议的资源与授权服务器发现规则；避免将访问其他服务的 token 原样透传。[MCP Authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)

## 5 工具调用治理

每次调用都需确定调用主体、工具版本、输入 schema、目标资源范围和有效授权。工具声称只读只是提示；真正权限由连接配置和业务策略决定。

工具输出属于外部数据，可能包含诱导执行的文字。不得将其提升为配置修改、权限批准或凭据导出的依据。超大输出以截断提示和受控产物引用返回，不能直接无限塞进模型上下文。

工具列表发生变化时缓存失效，新工具默认没有旧工具的写入授权。资源读取、提示模板加载和工具副作用分别计量；MCP 不等同于“所有应用都可无条件控制”。

需要接入无 MCP 的应用时使用官方 API Adapter；只读文档下载与业务写入仍分开。没有必要为了统一外形将每个内部 Module 都改成 MCP 网络调用。

## 6 配置中心页面

| 页面 | 必填/关键字段 | 必须展示的结果 |
| --- | --- | --- |
| 模型 | 协议、endpoint、模型、secret_ref、预算 | 能力探测、响应延迟、失败原因 |
| Hermes | 地址、Profile、凭据、实例归属 | 版本、执行位置、管理能力 |
| Codex/Claude | 节点、可执行入口、认证状态、能力 | 版本、可运行目录、审批支持 |
| MCP | 传输、节点、来源、参数、权限 | 工具列表、最近调用、进程状态 |
| 日历/邮箱 | 账号、授权范围、同步方向 | 游标、最近成功、权限过期 |
| 推送 | 渠道、目标、模板、勿扰 | 测试消息回执与可能费用说明 |
| 主机/设备 | 主机身份、设备权限 | 在线状态、撤销入口 |
| 性能 | 节能策略、并发、内存/输出预算 | 当前占用与设置影响 |

测试连接使用明确、低副作用探测；发送测试邮件/推送前显示实际目标和内容。配置保存成功与连接测试成功是不同状态。

## 7 配置作用域与生效

优先级为运行快照覆盖 Profile、Profile 覆盖空间默认；设备路径和平台配置始终属于设备，不被空间配置覆盖。安全限制取各层更严格的交集，不使用普通覆盖逻辑扩大权限。

设置需要 schema_version、revision、校验结果和生效方式。可热更新的配置发布变更事件；需重启的连接在空闲后重建，正在运行的任务继续使用既定快照。

导入外部 Hermes/Codex/Claude/MCP 配置首先呈现来源与字段映射，不直接覆盖；不兼容字段保留为未导入记录。导出默认去掉 secret，仅保留需要重新授权的引用。

## 8 凭据存储

Windows 用户模式使用 OS 保护的秘密存储；服务模式由专用服务身份保护。macOS 用户与系统 daemon 的秘密访问不同，必须分别验证，不依赖用户登录 Keychain 在无人登录时一定可用。

数据库、日志、SSE、错误提示和诊断包不保存明文凭据。子进程只拿到该任务允许的最少凭据，并限制其日志输出。授权的工具本身能使用其拿到的凭据，这种风险不能靠“环境变量”这个载体消除。

LAN 客户端只持设备凭据；主机的模型 API Key 不下发给所有客户端。需要本机直连模型时，该设备建立自己的独立连接和授权。

## 9 技能与插件

首版支持用户选择的技能文件包、只读资源和 MCP 连接。每包保存作者、来源、版本、摘要、许可、支持引擎与能力请求。新版本新增权限需重新确认，自动更新不能扩权。

将 Hermes 技能格式适配为目录元数据时，保留来源和不支持字段；不假设同一个技能文件在所有执行器上语义一致。系统依赖和可执行脚本属于额外安装能力，基础技能导入不能自动运行它们。

## 10 实施验收

至少建立以下真实验证矩阵：一个 OpenAI 原生端点、一个 Anthropic 原生端点、一个本地模型、一个 stdio MCP、一个带认证远程 MCP。账号不可用时记录未测，不能用模拟成功代替外部验收。

每个连接覆盖：凭据失效、权限不足、schema 变化、429/重试、断线、取消、超大结果和禁用后停止新调用。性能验收同时检查外部进程数、重启频率和队列长度。
