# 采用 WPF 原生 Windows 客户端

状态：设计基线，待 S0 技术验证。

项目明确要求原生 Windows 应用，并需要托盘、后台通知、透明桌宠和可安装体验。选择 C#/.NET 与 WPF 承担 Windows 界面，业务核心独立为无 UI 的 .NET 宿主，使 Windows/macOS 服务部署不依赖 UI 技术。

没有选择复用 Hermes 的 Tauri/Web 前端，因为这不符合当前原生界面约束。WinUI 3 是原生备选；Avalonia 在完整跨平台桌面成为硬需求时再评估。当前不为未经测量的性能收益承担全量 C++ 重写成本。

代价是 WPF UI 仅支持 Windows，Mac 客户端需要单独设计或迁移；因此产品首期只承诺 macOS 无界面主机。性能以分进程生命周期、虚拟化与实际测量约束，不以语言标签保证。
