# sol6.1 max 执行交接

此文档交给后续使用 sol6.1 max 的开发阶段。当前仓库只完成产品与架构设计；用户尚未在本阶段要求开始编写应用代码。实施应在用户明确启动后进行。

## 1 首先读取

按顺序阅读 README、领域术语、产品范围、系统架构、性能计划、交付路线和本文，再按当前阶段阅读专题。架构取舍见 docs/adr；能力与来源见依据文档。

不要将文档中的规划路径或接口表当成已有实现。开始时先检查实际工作区、适用指令、现有变更和已有代码；若后续已有阶段成果，从当前状态继续，不能重建覆盖。

## 2 不能偏离的产品要求

- 原生、可安装的 Windows 应用；业务 UI 不使用 Web 套壳。
- 主业务、后台调度、设置和安装不使用 Python 脚本拼接。
- Hermes 是实际外部引擎接入，可远程或可选独立运行包。
- 待办与日历不依赖模型可用性；关闭主窗口后可继续后台运行。
- 支持 Codex 与 Claude Code 的受控委派，并保留审批、取消、结果和验收区分。
- 支持 MCP、配置、不同模型协议、邮件/推送、桌宠与 LAN 服务。
- macOS 第一目标为服务主机，不默认扩展完整 Mac UI。
- 性能预算从第一阶段测量，不能在末期才检查内存与空闲占用。
- 参考 Hermes 交互和契约，不复制现有用户数据、凭据或完整安装目录。

## 3 第一个实施任务

用户明确启动后，先做 S0。验证最小原生窗口、后台宿主、通知激活、透明窗口与关键执行器契约，形成实测记录，再确定技术基线。

若用户要求直接实现 S1，仍先完成 S1 必需的最小平台验证，避免开发到后期才发现后台生命周期或通知激活不可用；不要顺势开展全部集成。

最早的业务闭环为：用户输入待办 → 核心校验 → SQLite 事务提交 → 返回 ID/revision → 原生列表显示 → 关闭重开后仍存在。该闭环稳定后再加入提醒与 AI。

## 4 每个工作包的说明

| 项目 | 必须回答 |
| --- | --- |
| 行为规则 | 用户输入什么，预期结果是什么，边界场景怎样处理 |
| 类似功能 | 已有哪段功能/官方契约可以复用，是否确实兼容 |
| 数据链路 | 哪个入口、用例、存储、事件和 UI 发生变化 |
| 修改位置 | 将修改哪些具体工程/目录/类型，为什么在那里 |
| 验证方式 | 需要哪些小范围规则测试、集成或原生交互检查 |
| 性能预算 | 会增加什么常驻工作、数据量、进程或延迟 |
| 完成定义 | 什么证据足以说明该工作包完成 |

在给定阶段完成规则和核心，再接存储与 Interface，最后接原生 UI；不要先做能展示但没有数据一致性的页面。

## 5 实现结构

保持 Domain 不依赖 WPF、HTTP、数据库或具体执行器。Application 承载业务用例与授权；Infrastructure 和 Integrations 实现实际变化的 Adapter。只有真实复用与变化时才增加抽象。

客户端、桌宠、渠道和 AI 通过同一个业务 Interface，避免重复规则。核心数据库由一个权威主机拥有；远程客户端和执行节点不得直接打开正式数据库。

Hermes 对接先能力查询和运行，再决定是否支持版本相关管理操作。Codex/Claude 依据实际版本的官方协议接入，不控制桌面应用私有状态。

## 6 变更与验证纪律

每次只实现一个可验收工作包，保护已有用户变更；外部源码与安装目录保持只读，除非另获明确修改授权。秘密不写入仓库。

测试优先覆盖关键业务不变量、幂等、状态转换、时间/重试与权限；不为纯文案等可逆低影响改动制造镜像测试。平台生命周期、安装、通知、DPI 和透明窗口必须在原生环境验证。

性能先得到 Release 基线，再分析实际瓶颈。不要为了目标数字关闭持久化和权限，不以强制 GC 或排除所有子进程美化报告。

实际账号、macOS 设备或服务注册条件不足时，继续完成可独立工作，并准确标注外部未测。不要把 Stub、模拟输出或静态阅读写成完整集成。

## 7 外部副作用

明确的用户授权可以覆盖一类既定操作，无需每步重复询问；但生成提案、执行工作区变更、提交 Git、推送、发邮件、删除和发布是不同影响，按用户实际授权范围处理。

当前用户授权的是本轮文档项目公开发布。此授权不应被扩展为未来每阶段自动发布软件、自动发送邮件或扩大执行器权限。

## 8 阶段结束报告

报告应包含：完成的用户行为、实际改动、通过的验证、未运行的验证、性能测量环境和结果、已知问题与下一阶段依赖。阶段内历史测试结果不要混成一个夸大的总数。

区别以下状态：已设计、已实现、静态检查通过、集成验证通过、原生视觉验收通过、安装验证通过、已发布。只有对应证据存在时才能使用后面的状态。

每个阶段结束保留可回退版本和数据备份，停在阶段交接点等待用户反馈。不得因为空余时间擅自进入所有后续阶段。
