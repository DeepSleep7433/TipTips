# 分阶段交付路线

实施按可验收闭环推进，每阶段先固定行为规则，再完成领域/核心、持久化、接口和原生界面，最后验证当前阶段。不要先铺开所有 UI 或一次生成全产品骨架。

阶段结束后交付当前可运行结果、对应文档、验证证据和未解决事项，等待所有者反馈再进入下一阶段。性能与权限属于阶段内工作，不留到最后补救。

## 1 依赖关系

S0 技术验证 → S1 本地任务 → S2 日历调度 → S3 直连助理 → S4 Hermes/MCP → S5 编码委派 → S6 外部日历与消息 → S7 桌宠 → S8 LAN/服务 → S9 完整发布。

部分工作可在已有契约稳定后并行，但写同一 Module、数据库迁移和共享工作区的任务必须协调。此文档不授权在当前文档阶段启动子代理编程或实际开发。

## 2 S0 技术和契约验证

**目的**：提前验证影响全局架构的高风险假设，并得到首个可测的原生进程组合。

| 工作包 | 行为与产出 | 验证/通过条件 |
| --- | --- | --- |
| S0-01 | 确认 OS/SDK/打包基线，创建最小原生窗口与核心 | 主 UI 无 WebView，清洁系统可启动 |
| S0-02 | 验证 SessionAgent、窗口关闭、通知激活 | 主窗口退出后代理仍可唤起界面 |
| S0-03 | 验证 WPF 小型透明窗口与混合 DPI | 可拖动、可关闭、静止停止刷新 |
| S0-04 | 验证 CoreHost 在 Windows 与 macOS 的最小宿主 | 无 WPF 依赖，正常停止与重启 |
| S0-05 | 对固定版本 Hermes 做无副作用能力/运行探测 | 明确能力、认证、执行位置和停止语义 |
| S0-06 | 验证 Codex/Claude 官方入口、版本和结构化输出 | 不依赖桌面私有接口；记录审批缺口 |
| S0-07 | 建立启动、空闲 CPU/内存和 IPC 初始基线 | 提供实测环境和原始数据，非口头判断 |

这些验证只能在所有者启动实施后进行。若某项失败，先修订相关 ADR 与阶段范围，不靠跳过权限、改 Web 壳或取消服务目标掩盖问题。

## 3 S1 本地原生待办与数据核心

涉及 M01、M02、M14、M18、M19、M20、M21 的基础部分。

1. 定义任务、项目、收件箱和日期型截止规则，建立最小领域对象。
2. 建立数据库迁移、任务存储、操作去重、revision 和 Outbox。
3. 完成新建、查询、修改、完成、重开、软删除与恢复 Interface。
4. 提供本机认证通信与今天/收件箱/任务原生页面。
5. 完成快速捕获、登录自启动选项、托盘和主窗口退出语义。
6. 建立非敏感设置、备份导出和诊断基础。

**验收**：无模型离线可用；重启数据不丢；重复提交只生成一个对象；并发冲突可理解；完成/重开与软删除一致；一万条任务达到 S1 性能门槛。

**交付**：可安装预览、数据模型说明、恢复步骤和原生 UI 验收记录。此阶段不宣称完整助理功能。

## 4 S2 日历与可靠提醒

涉及 M03、M04、M05。

1. 实现内置日历、时间块、日期/时点/全天语义。
2. 选择并验证重复规则库，保存规则、例外与有限范围展开。
3. 实现持久调度、租约、触发去重、错过规则与重叠策略。
4. 实现通知意图、Windows Toast、动作、延后和勿扰。
5. 实现日/周/月/议程视图与拖动排期。

**验收**：DST、31 日重复、修改单次/以后、休眠恢复、核心重启、投递重复、主窗口关闭、通知点击。验证提醒不会完成任务、完成任务会取消未来提醒。

**交付**：本地核心预览。外部日历和邮件可尚未提供，范围写明。

## 5 S3 会话与直连模型

涉及 M06、M07、M11、M14。

1. 实现 Conversation、Message、Profile、Run、Proposal 和基础审批数据。
2. 完成模型配置、凭据保护、能力矩阵和预算预留。
3. 逐个实现 OpenAI、Anthropic、本地模型 Adapter。
4. 实现会话分页、原生消息渲染、流式刷新与取消。
5. 为助理提供有限的待办/日程业务工具，建立提案落地与版本复核。

**验收**：用户输入先保存；连接失败/429/不支持工具有明确信息；私密本地任务不自动转云；越权提案被阻止；十万消息历史不全量加载。

**交付**：可通过对话整理计划的助理预览，提供三个协议类别的真实验证或明确未测记录。

## 6 S4 Hermes MCP 技能与记忆

涉及 M08、M10、M12、M13，并扩充 M04/M19。

1. 固定 Hermes 版本与能力，接入会话、异步运行、事件、审批和停止。
2. 建立 TipTips 业务工具入口，并验证引擎工具运行位置。
3. 实现 stdio 和 Streamable HTTP MCP 的配置、发现、授权和生命周期。
4. 实现技能目录、版本/来源、启停与权限变化。
5. 实现可纠正的记忆、全文搜索和基于实际记录的回顾。
6. 加入有预算的 AI 自动化；与 Hermes 原 Cron 保持清晰归属。

**验收**：引擎未启动不影响待办；MCP 输出注入不能扩权；断线先对账；禁用连接阻止新调用；删除记忆同步清理派生索引。

**交付**：Hermes 助理闭环与连接中心。管理 Hermes 配置的扩展只在契约验证通过后加入。

## 7 S5 Codex 与 Claude Code 委派

涉及 M09、M22，并扩充 M17/M19。

1. 实现委派目标、验收条件、节点与工作区绑定、运行尝试和产物。
2. 实现进程监督、写入互斥、输出限额、预算和取消。
3. 接入 Codex app-server；根据能力保留有限非交互入口。
4. 接入 Claude Code 程序化模式；需要双向审批时验证可选 SDK 宿主。
5. 实现运行详情、审批、产物查看、待验收和继续修改。

**验收**：只读分析、限定写入、权限拒绝、输入等待、超时、进程崩溃、停止进程树、核心重启、未知结果对账、两个写任务竞争工作区。

**交付**：两种执行器分别有真实证据。不能将一种成功写成两种均完成，也不能将运行成功写成代码已正确。

## 8 S6 外部日历与消息渠道

涉及 M03/M05/M15。

1. 完成 ICS 与一个外部日历只读同步，再实现其双向冲突处理。
2. 完成邮件连接、授权范围、发送、回执和失败处理。
3. 实现已绑定邮箱的有限回复动作与会话关联。
4. 实现一种选定推送渠道，统一勿扰、去重、合并和升级。
5. 增加自动化触发与渠道输入的防循环规则。

**验收**：游标过期、订阅续期、重复消息、取消事件、发送超时、退信、伪造发送者、重复动作、敏感指令转可信客户端。

**交付**：可通过邮件/推送与用户持续交互的版本，公开说明具体支持渠道。

## 9 S7 桌宠

涉及 M16。

1. 固定资源清单与状态映射，做资源大小和路径校验。
2. 实现原生透明窗口、命中区域、拖动、气泡和关闭。
3. 接入快速捕获、今日任务、提醒和运行摘要。
4. 实现省电、静止停帧、锁屏隐藏和多屏 DPI。

**验收**：不抢焦点、可完全关闭、无越权操作、软件渲染和长空闲性能达标。素材来源与许可证完整。

**交付**：可选桌宠预览，核心使用不依赖桌宠开启。

## 10 S8 局域网与服务部署

涉及 M17，并扩充 M18/M19/M20。

1. 实现 TLS、主机身份、设备配对、撤销与权限。
2. 实现 LAN 请求/事件续传、快照和明确缓存状态。
3. 实现节点主动连接、能力匹配、租约与旧结果拒绝。
4. 实现 Windows Service 与 macOS daemon 安装、停止和升级。
5. 实现显式主机迁移、离线捕获与冲突处理。
6. 验证多设备提醒策略和主机独立运行。

**验收**：无登录桌面的服务运行、主机断网、客户端断网、设备撤销、证书变化、主机迁移、节点失联、不同 OS 路径和跨机工作区。

**交付**：真实 Windows 客户端连接独立 Windows/macOS 主机的记录；缺少 Mac 设备时必须标记该平台未验收。

## 11 S9 发布与性能收敛

1. 完成各支持平台的签名/安装条件、升级和卸载验证。
2. 完成 24 小时稳定性、大数据增长、故障恢复和整树资源测量。
3. 验证备份恢复、加密秘密迁移限制和版本兼容矩阵。
4. 完成用户帮助、故障指引、隐私与第三方许可清单。
5. 核对完整需求矩阵后形成正式发布说明。

**验收**：R01–R12 均有对应功能或经用户接受的明确范围调整；不能以延期列表代替原始完整需求。性能目标未达项必须给出瓶颈、影响和处理决定。

## 12 跨阶段关键用例

| 编号 | 输入或故障 | 必须结果 | 所属阶段 |
| --- | --- | --- | --- |
| A01 | 相同 operation_id 重发 | 一个业务结果，同 ID 不同内容报冲突 | S1 |
| A02 | 更新对象前被另一设备修改 | 返回冲突，不覆盖新状态 | S1/S8 |
| A03 | 核心提交后 UI 断线 | 重连可查询原结果 | S1 |
| A04 | 提醒领取后核心崩溃 | 恢复处理不产生重复通知意图 | S2 |
| A05 | 电脑睡过多个周期 | 按明确 misfire 上限补偿 | S2 |
| A06 | 重复事件修改单次 | 其他实例保持不变 | S2 |
| A07 | 本地私密模型不可用 | 不自动上传云端 | S3 |
| A08 | 提案之后对象版本变化 | 提案 stale，不错误应用 | S3 |
| A09 | 工具输出要求读取凭据 | 不扩大授权 | S4 |
| A10 | Hermes API 流断开 | 查询外部 run，不盲目重建 | S4 |
| A11 | 工具目录新增写工具 | 无自动继承写权限 | S4 |
| A12 | 同工作区两个写委派 | 串行或隔离目录 | S5 |
| A13 | 用户取消运行 | 保留 cancel_requested 直到确认 | S5 |
| A14 | 执行器成功但验收失败 | 委派仍未 accepted，任务未 done | S5 |
| A15 | 邮件已发但响应丢失 | unknown/对账，不直接重发 | S6 |
| A16 | 相同回复从渠道重投 | 一次业务动作 | S6 |
| A17 | 桌宠隐藏或锁屏 | 停止动画工作 | S7 |
| A18 | 旧节点租约回报 | 拒绝过期写入并保存诊断 | S8 |
| A19 | LAN 主机失联 | 显示缓存，不启动第二权威主机 | S8 |
| A20 | 迁移后启动已退休旧主机 | 退休标记阻止调度，旧凭据不可继续产生外部副作用 | S8 |
| A21 | 更新中断或备份损坏 | 可恢复且不覆盖可用数据 | S9 |
| A22 | 历史数据增长十倍 | 内存不按历史正文线性增长 | 持续 |
| A23 | 未提供真实账号/设备 | 标注未测，不伪造外部成功 | 持续 |

## 13 工程工作包写法

每个实现任务写清：行为规则、类似功能或官方接口、数据链路、修改位置、验证方式、资源预算和完成定义。不要仅分配“完成后端”“接好 MCP”或“优化性能”。

一个工作包应能独立说明通过与否；出现新的外部权限、平台限制或不兼容协议时先记录具体事实，再修订对应范围。不以大量低价值测试替代真实接口与原生交互验收。

## 14 排期方法

不以模型名称直接推算交付天数。S0/S1 后根据实际速度、平台条件和外部集成难度估算后续工作量，分别记录开发、外部接入等待、视觉验收和发布准备。

优先缩小一次交付的范围，保持完整产品目标；每阶段进入下一阶段前由所有者反馈确认方向，避免大批未验收功能叠加。
