# 原生界面与交互规格

TipTips 的主界面应让用户快速回答四个问题：今天要做什么、时间如何安排、助理在做什么、现在是否需要我处理。界面参考 Hermes 的功能分组，采用独立 WPF 视觉与交互实现。

## 1 主窗口结构

| 区域 | 内容 | 交互规则 |
| --- | --- | --- |
| 顶部 | 快速捕获、全局搜索、当前主机/离线状态 | 搜索和捕获始终可达 |
| 左侧导航 | 今天、收件箱、任务、日历、助理、委派、自动化、连接、设置 | 常用项目可固定，不把全部配置项塞进第一层 |
| 主内容区 | 当前列表、日历、对话或运行 | 页面切换不重复加载全部历史 |
| 可选详情面板 | 对象详情、提案、审批、产物 | 与主列表选择同步，可独立关闭 |
| 状态入口 | 正在运行、等待处理、连接问题 | 不用常驻日志面板占满界面 |

主窗口支持调整大小、系统缩放、浅深色、系统字体、键盘导航和屏幕阅读器。默认中文，数据结构与文案资源支持后续多语言。

## 2 页面规格

| 页面 | 首屏内容 | 主要操作 | 异常与空态 |
| --- | --- | --- | --- |
| 今天 | 逾期、今日任务、下一日程、待处理审批 | 完成、延后、安排、查看 | 无事项给出快速记录，不制造虚假建议 |
| 收件箱 | 原始输入及来源、整理状态 | 转待办/日程、合并、保留参考 | AI 未整理仍显示原文 |
| 任务 | 分组列表、筛选、项目、标签 | 批量编辑、依赖、归档、排序 | 部分批量失败逐项保留 |
| 日历 | 时间网格、全天区、任务侧栏 | 拖动排期、查看冲突、修改系列 | 外部只读、同步滞后清楚标识 |
| 助理 | 会话列表、消息、关联资料、输入区 | 发送、停止、选 Profile、查看提案 | 模型不可用时输入仍能保存 |
| 委派 | 目标、执行器、节点、运行状态 | 创建、取消、补充、验收 | 结果未知和失败使用不同提示 |
| 运行详情 | 摘要、阶段、工具、审批、产物 | 查看变更、打开日志、处理审批 | 断流显示重连，不提前显示完成 |
| 自动化 | 规则、下一次运行、通知策略 | 预览、启停、手动触发 | 能显示错过规则与重叠策略 |
| 连接 | 模型、引擎、MCP、渠道、日历 | 添加、测试、授权、禁用 | 版本不兼容、权限失效各有操作 |
| 记忆 | 用户偏好、候选事实、来源 | 确认、修订、删除、禁止记忆 | 推断信息不显示成已确认事实 |
| 设置 | 启动、提醒、桌宠、主机、性能、备份 | 修改并验证生效 | 保存与待重启状态分离 |
| 诊断 | 各模块健康、资源、队列、近期故障 | 导出脱敏信息、重试连接 | 不要求用户阅读堆栈才能恢复 |

## 3 新用户引导

先选择本机个人模式或连接主机，再确认数据位置、时区、是否后台运行和通知偏好。完成这些即可使用待办与内置日历。

模型、Hermes、编码执行器、邮件和桌宠是后续可选步骤；不把 API Key 作为进入待办功能的门槛。连接主机通过配对流程完成，不要求用户直接编辑配置文件。

## 4 快速捕获

全局快捷键唤起小窗口，用户输入后立即保存。支持文本和必要附件拖入，清楚显示保存到哪个空间。自然语言解析在保存后进行，日期、项目和优先级形成可编辑候选。

普通记录无需 AI 动画或长等待。网络失败时保存本地草稿并显示待同步；客户端离线不能提示“主机已保存”。

## 5 对话与提案

文本、工具结果、系统状态和操作提案以不同原生控件呈现。不会把系统错误伪装成助理自然语言，也不展示模型不可用的内部推理过程。

提案卡显示操作对象、变化前后、影响范围和可撤销性。用户已有明确授权时可直接显示已执行结果；额外授权才展示确认。多项计划逐项选中并报告部分成功。

长会话采用分页和 UI 虚拟化，输入框不随历史重排。流式生成时以短间隔合并刷新，仅更新末尾活动消息，滚动阅读历史时不强行跳到底部。

## 6 委派与审批

创建委派时依次选择项目、执行节点、工作区、执行器和完成条件。高级区配置预算与权限，默认值始终可见。

审批必须显示“谁申请、在哪执行、改什么、权限有效到何时”。审批结果跨设备只消费一次；过期后按钮失效。来源文件和工具描述中的指令不能变成审批文案的可信身份。

运行详情先呈现有用摘要，再允许展开工具记录。产物页分别列出文件、代码变更、验证结果和未解决项。提供接受结果、继续修改、重新运行等清楚入口。

## 7 桌面系统交互

关闭主窗口后允许释放主进程，由 SessionAgent 承接提醒与重新激活。需要保留正在编辑的未提交内容时先保存草稿；不要求在关闭窗口时保持大历史缓存。

托盘菜单区分“暂停自动化”与“停止本机后台”。远程模式关闭本机前台不应误停远程主机，UI 要显示操作对象。

链接通过系统浏览器打开；OAuth 登录使用系统浏览器与受限回调。业务页面不引入内嵌浏览器作为渲染基础。

## 8 可访问性与边界状态

核心流程无需鼠标也能完成。按钮有可读名称，颜色不作为唯一状态依据，焦点可见，尊重系统减少动画和高对比设置。中文输入法组合输入不应被快捷键提交打断。

必须设计：加载中、空态、局部错误、离线、权限不足、对象已删除、版本冲突、引擎不支持和更新维护。数据新鲜度与当前主机在远程模式可见。

主窗口与桌宠均按每显示器 DPI 重新布局，显示器移除后回到可见区域。快捷键配置冲突时明确提示，不能影响其他应用正常输入。

## 9 视觉验收

每阶段使用真实 Windows 原生窗口验收，不以网页原型或 HTTP 结果代替。至少覆盖 100%/150%/200% 缩放、浅深色、窄窗口、长中文、键盘、屏幕阅读器基础语义和长列表。

本阶段只定义交互，没有创建 UI 代码、截图样机或已验证的渲染结果。
