# 部署安全与运维

安装、后台生命周期、主机身份和数据恢复应与业务功能同时设计。单机模式不要求管理员权限；系统服务和 LAN 访问作为明确启用的能力。

## 1 发布物

| 发布物 | 平台 | 作用 |
| --- | --- | --- |
| Windows 客户端安装器 | 首先 Windows 11 x64 | 主窗口、会话代理、可选本地核心和桌宠 |
| Windows 服务安装器/可选组件 | 受支持 Windows | CoreHost 作为系统服务，独立数据与服务身份 |
| macOS 服务包 | 分别验证 Apple Silicon 与 Intel | CoreHost 与可选执行节点，不包含 WPF |
| 可选引擎组件 | 按供应方平台矩阵 | Hermes/CLI 依赖或连接向导，与主版本解耦 |
| 恢复/导出能力 | 各主机 | 可验证备份、诊断与迁移 |

候选 Windows 安装技术为成熟 MSI/EXE 工具链，实施前核实当时许可证、升级能力和服务支持。MSIX 可在身份、通知与分发需求明确后评估，不要求首版所有组件共用一种打包方式。

MIT 是源码和文档的开源许可证；安装包代码签名证书是另一项发布条件。拥有 MIT LICENSE 不会自动获得 Windows 签名或 macOS 公证。

## 2 本机个人模式

普通用户安装到用户可写的软件目录，业务数据与程序文件分开。CoreHost 以用户身份运行；登录时启动是用户选择项。未登录时不承诺用户后台继续运行。

本机通信优先经过受 ACL 保护的本地通道。若使用回环 HTTP，仍需每安装身份认证、Origin/Host 校验与访问限制；回环地址不是认证机制。

双击程序由 SessionAgent 或单实例协调机制激活现有会话。UI 崩溃不终止已持久化的调度；用户停止核心时停止领取新任务并显式处理正在执行的任务。

## 3 Windows Service

服务采用专用低权限身份，数据目录 ACL 只允许该身份与授权管理者；不以 LocalSystem 作为默认执行所有工具的方式。安装、注册服务与防火墙规则由用户授权的安装流程完成。

服务负责业务、调度和远程投递；SessionAgent 在登录用户桌面负责通知与宠物。服务不能继承用户交互桌面的登录凭据和浏览器 OAuth 状态。

编码执行器可以运行在用户节点或服务专用节点。依赖交互认证的执行器需要明确登录和授权流程；不得复制用户的私有认证文件给服务账号。

## 4 macOS 主机

用户级后台使用 LaunchAgent，登录后运行；无人登录仍需服务则采用 LaunchDaemon、专用身份和独立数据/凭据访问。两者的生命周期不能混淆。[Apple launchd 指南](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html)

发布分别考虑 arm64 与 x64、自包含 .NET 运行时、目录权限、日志轮转、停止信号、升级和签名公证。具体支持的 macOS 版本在实施时根据 .NET 与依赖的官方支持矩阵确定。

Mac 主机运行的工具只操作其已授权目录；Windows 客户端目录通过绑定到该 Windows 执行节点的任务访问。

## 5 局域网身份与配对

初始主机仅监听本机；启用 LAN 时选择绑定网卡、访问范围和服务端口。主机生成身份与 TLS 配置，客户端通过短期一次性配对码及主机指纹确认连接。

配对完成后发放独立设备凭据，支持到期、轮换和撤销。个人空间管理员、普通设备访问和执行节点能力分开；设备凭据不等于模型 API Key。

可使用受信任证书或经过配对固定的主机证书。不能通过全局关闭 TLS 校验解决自签名问题。证书轮换建立有签名或人工确认的信任迁移；指纹突然变化时阻止连接并解释。

发现机制可提供 mDNS 等便利，但发现结果不是身份认证；手动地址始终可用。LAN 不是可信安全区域，不默认开放任意终端执行、数据库端口或无认证 MCP。

## 6 执行节点

节点向主机主动发起经过认证的连接，报告平台、执行器版本、允许工作区、能力和资源预算。主机只把匹配授权的工作分配给节点。

领取具有租约和 fencing token；节点回报包含 authority_epoch，旧主机或旧租约不能提交新结果。断连时根据预定策略停止新的副作用；已启动任务有明确继续/停止约定。

同一工作区采用写入互斥；外部进程崩溃时回收进程树并保留产物。真正的文件与网络隔离依赖操作系统及执行器支持，不能用队列互斥冒充沙箱。

## 7 安全控制

| 风险 | 设计要求 | 验证方式 |
| --- | --- | --- |
| 工具输出或邮件提示注入 | 内容只作数据，授权必须来自可信主体 | 注入内容不能批准新权限 |
| 工作区路径越界 | 规范化、解析重解析点、固定根、再次检查 | 链接/挂载/大小写路径逃逸用例 |
| LAN 未授权调用 | TLS、设备凭据、空间权限、限流 | 无凭据和已撤销设备被拒绝 |
| 连接端点滥用 | endpoint 与访问范围由用户配置，重定向后复查 | 防止模型自行访问未授权内部服务 |
| 凭据泄露 | OS 秘密存储、最小注入、日志脱敏 | 导出包与异常日志检查 |
| 插件替换 | 版本/来源/摘要固定，升级重新评估权限 | 工具 schema 变化与新增权限用例 |
| 资源耗尽 | 大小、时间、并发、磁盘与预算上限 | 超大消息、无限输出、慢消费者 |
| 外部重复副作用 | 幂等与对账、unknown 状态 | 发送后网络断开用例 |

安全控制先实现与当前功能相关的部分；不为纯本地待办阶段引入完整企业 IAM。

## 8 备份与数据迁移

备份包括一致数据库快照、附件清单与摘要、非敏感配置、迁移版本和空间身份。凭据默认不明文导出；可选可迁移凭据备份需要单独加密及恢复密钥说明。

保留策略建议每日滚动、每周较长保存，并允许用户指定磁盘位置；具体数量由存储预算决定。备份路径不能位于会被自身重复打包的目录。

恢复先写入临时独立位置，执行完整性和附件验证，然后停止核心、原子切换并保留原副本。错误备份不能覆盖当前可用数据。

从本机迁移到 LAN 主机时停止旧调度、记录最终游标、校验导入、变更权威代次、重新配对或更新绑定，最后启用新主机；不同时启动两套同一空间调度。

旧主机保存退休标记并禁用服务，必要时撤销其专用外部凭据。仅有 epoch 无法拦截一个脱离新主机、仍能直接访问邮件服务的旧进程。备份恢复后先进入待激活模式，完成主机身份和凭据检查再允许调度。

## 9 升级与回滚

更新清单包含版本、平台、组件、摘要、签名、最小核心版本和数据迁移要求。先下载校验，再暂停新任务、等待或处理运行、备份和升级。运行中的编码任务不被无提示强杀。

数据库迁移以互斥、事务和版本记录控制。不可逆迁移后的程序降级需要恢复兼容备份；仅替换旧二进制不算完整回滚。

Hermes 与外部 CLI 更新独立于 TipTips；新版本先通过契约测试，允许锁定旧版本。不要直接以“最新”作为所有运行环境的隐式版本。

## 10 诊断与保留

存活检查只表示进程可回应；就绪检查确认数据库、迁移和关键队列已可用；模型、Hermes、渠道等可选依赖故障不应让本地待办整体不可用。

诊断包包括版本、配置摘要、连接状态、队列与延迟、经过脱敏的关联日志。默认不含对话正文、邮件、文件内容或凭据。日志按大小和时间轮转，并显示总占用。

运行产物、会话、审计、通知与备份分别设置保留期；手动清理提供占用与影响预览。磁盘不足时优先停止新大产物与非关键日志，不破坏业务提交和已有数据。

## 11 发布验收

真实系统验证：清洁 Windows 安装、普通用户启动、服务模式、用户注销、重启、休眠恢复、离线、卸载保留数据、升级中断和恢复。macOS 服务包在真实受支持系统上独立验收。

只有打包成功不能称为安装可用；只有 HTTP 请求成功不能称为原生桌面交互验收；本阶段没有执行这些应用测试。
